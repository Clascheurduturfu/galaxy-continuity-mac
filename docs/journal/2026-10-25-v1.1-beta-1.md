# 2026-10-25 — v1.1 beta 1: Closing the Multi Control Smoothness Gap

Three fixes derived from the decompiled Galaxy Book client
(`MultiControl 2.7.1300.0`, `MCFMessage.cs` / `MultiControl.cs`), targeting the
remaining ways the Mac pipeline feels worse than native.

## Changes

1. **Wheel rate limiting (`WheelPacer`, `PointerPacer.swift` / `PhoneInputCapture.swift`):**
   The Book's `SendMouseEvent` drops 11 of every 12 wheel events when the source
   is a precision touchpad (`wheelCount %= 12`). macOS trackpad and momentum
   scroll streams are now decimated the same way — one `W` packet per 12
   continuous events — but skipped deltas are **accumulated** so the phone
   scrolls the full distance (the Book can drop them because Windows PTP wheel
   deltas are tiny notch fractions). Discrete mouse-wheel notches (no scroll or
   momentum phase) pass straight through, matching the Book's touchpad-only
   gating; gesture/momentum end flushes the tail.
2. **Reliable-channel inputs left the main actor (`ReliableInputSender`, `FeatureSession.sendFromWorker`, `Transport.sendFrameBlocking`):**
   Keys, clicks, wheels and TCP-fallback movements were drained by a
   `Task { @MainActor }` consumer, so every keystroke waited behind SwiftUI
   work. They now go straight from the capture worker onto the TCP channel
   (`NWConnection.send` is thread-safe; the write blocks only until the TCP
   stack accepts the frame, bounded at 1 s). The primary channel sits in a
   lock-protected box so a concurrent disconnect either waits for the frame or
   fails the send — it can never interleave. Held keys/buttons are tracked in
   the sender itself and released on hand-back (`releaseHeld`).
3. **UDP QoS marking on by default (`PointerOptions.ipTOS = 0xC0`):**
   The Book applies `ApplyQoSPolicyAsync(UDP, LowDelay, 48)` (DSCP CS6) to its
   mouse datagrams on every connect; the Mac socket previously only set
   `SO_NET_SERVICE_TYPE` (responsive data). The `IP_TOS 0xC0` default now
   matches the Book; `CONTINUITY_POINTER_IPTOS=0` downgrades to best effort.

## Release process change

`release.yml` (preview channel) now deletes earlier pre-releases before
creating the new one, leaving a **single rolling preview release**; the git
tags of deleted releases are kept. The updater is unaffected: it still matches
tag `v$version` against the ZIP's `CFBundleShortVersionString` and only offers
releases newer than the running version.

## Verification

- New unit tests: `WheelPacer` decimation/tail/discrete behavior, CS6 default
  and explicit downgrade; all existing `PointerPipelineTests` unchanged.
- CI (macos-15, Xcode 16.4) runs the full `swift test` suite via
  `scripts/build-macos.sh` before packaging.

## Not addressed (the hard ~10%)

CGEvent-tap coalescing itself — macOS still delivers merged movement events
that Windows Raw Input never merges. IOHID-level capture is the known next
step if pointer micro-stutter remains after these fixes.
