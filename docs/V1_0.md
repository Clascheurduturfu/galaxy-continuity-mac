# v1.0 (55) — first stable release

Promotes the RC1 feature set to Stable on `main`: native Samsung sign-in, automatic nearby text/image clipboard peers, CMC calling, Galaxy Buds switching, Finder Storage Share, arranged screen-edge Multi Control, per-device Auto Hotspot, Contacts, and verified GitHub updates.

## Final changes

- Removed the **About the macOS Personal Hotspot menu** research section from Auto Hotspot. Native Samsung hotspot activation remains available.
- Removed **Temporary private repository access**, including token creation, entry, saving and branch-link controls. Public updates need no GitHub token. An existing private-build token is retained only for backward-compatible private access and deleted automatically after a successful public release check; this does not revoke it at GitHub.
- New installations default to **Stable**. Existing channel selections are preserved, and Preview remains available.
- Version is **1.0**, build **55**. No installed Mac app is replaced by this release preparation.

## Validation and known limits

Native Apple Silicon regression run passed **112 tests with zero failures**, and the signed release build passed. Fresh fictional UI renders verify removal of both sections. Final decoded archive checks and independent source/history review precede publication; downloaded assets are checked against the audited originals. The app identity and designated signing requirement remain compatible with prior versions.

The Buds system-sound filter requires macOS 14.2+ and still needs a live alert-versus-media acceptance check. A notification produced by the media app can still count as playback. Screen-edge Multi Control was owner-accepted; keyboard-layout mapping, broader sleep/wake and multi-monitor behavior remain follow-ups. Overseas native tablet calling was confirmed; this does not establish overseas Mac audio or an Internet clipboard relay. Distribution is Apple Silicon, locally ad-hoc signed; Intel hardware acceptance, Developer ID signing and notarization remain open.

A hosted-runner timing failure in the existing calling test was resolved by waiting for six packets with a three-second deadline, keeping the no-audio-before-answer assertion and packet-count threshold. Production calling code is unchanged.
