# 2026-10-25 — v1.1 beta 2: Auto Hotspot on demand + native Wi-Fi menu experiment

## Changes

1. **On-demand type-3 policy (`Hotspot.swift`, `ClipboardSession`, wiring in `App.swift`):**
   Queries now run only when the user acts (page button, Wi-Fi menu open,
   Wi-Fi menu click) — never on scan ticks. Answers are cached 20 s
   (`HotspotCenter`) and invalidated on wake, session end or manual retry.
   The watcher path reuses the existing BLE session only
   (`requestHotspotAnswer(timeout:)` suspends until the type-4 reply) and
   never opens a connection for a query. With no live session the Wi-Fi menu
   entry is hidden via a freshness file the hook checks.
2. **Hotspot capability memory (`HotspotCapabilityMemory`):** devices that
   answer type-3 with a failure are excluded from requests for 24 h — grayed
   card with Retry on the Auto Hotspot page, excluded from the menu entry.
3. **macOS Wi-Fi menu integration (`WiFiMenuHotspot.swift` + hook v5):** an
   option on the Auto Hotspot page. Requires SIP disabled (checked via
   `csrutil status`); installs the bundled hook dylib through
   `launchctl setenv DYLD_INSERT_LIBRARIES` and restarts WiFiAgent/
   ControlCenter. File protocol in `/tmp/gcl-wifi-menu` between app and hook
   (status/available →, menu_opened/trigger ←, creds.json →). Hook v5 is a
   defensive rewrite (the v4 sources were lost with `/tmp`), with the
   duplicate-entry fix: while connected to the hotspot SSID the fake entry is
   suppressed. Compiled into the app bundle Resources by
   `scripts/build-wifiagent-hook.sh` during the normal build.
4. **Research:** `docs/research/auto-hotspot.md` documents the PoC findings,
   the new file protocol, and an external research verdict — there is no
   documented SIP-enabled way to a native Personal Hotspots entry (private
   XPC-only, iCloud-keyed BLE, Tetherbug's beacon IE is the only partial
   alternative). The SIP-off hook remains the only known full route.

## Verification

- New tests: `HotspotPolicyTests` (cache store/invalidate semantics,
  capability memory trust window).
- CI (macos-15) compiles the hook dylib (clang, ARC) alongside the app;
  injection itself is only exercised manually on the SIP-disabled MacBook.

## Notes for testing on the Mac

- After updating to 1.1-beta.2: Auto Hotspot page → "Integrate with the
  Wi-Fi menu" → check SIP state. The entry appears once the phone session is
  live. `hook.log` in `/tmp/gcl-wifi-menu` tells which hooks landed.
- Turning the option off restores stock behavior (unsetenv + restart).
